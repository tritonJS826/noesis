# Лендинги noesis

Статический лендинг проекта. Он не подключён к Go-приложению, не собирается
вместе с бинарниками и не является отдельным UI: это обычная папка со
статическими файлами.

## Страницы и файлы

- `index.html` — единственный экземпляр главной страницы.
- `feedback.html` — единственный экземпляр страницы обратной связи.
- `thanks.html` — единственный экземпляр страницы после отправки формы.
- `content.json` — весь текст, заголовки, описания, подписи, ссылки на
  скачивание и метаданные. Внутри два языка: `ru` и `en`, плюс общий блок
  `shared`.
- `app.js` — загружает `content.json`, подставляет переводы в `data-i18n`,
  переключает язык, обновляет `<title>`, `meta description`, скрытое поле
  `language` и рисует карточки скачивания.
- `styles.css` — общий CSS для всех страниц.

Отдельных английских копий страниц больше нет: одна HTML-страница на экран,
а язык выбирается на клиенте.

## Язык

Приоритет выбора:

1. `?lang=ru` или `?lang=en` в URL;
2. `localStorage` с ключом `noesis.lang`;
3. язык браузера (`en` → английский, остальные → русский).

В шапке есть переключатель RU/EN. Он меняет текст на месте, обновляет адрес
через `history.replaceState` и запоминает выбор. Скрытое поле `language` в
формах обновляется автоматически, чтобы заявка приходила с языком страницы.

Весь контент лежит в `content.json`. В HTML остаётся только структура и
`data-i18n`-ключи. Если добавляете новый текст, добавьте его в оба языка —
`app.js` не делает машинный перевод и не подставляет русский вместо
английского.

## Скачивание

Секция `#downloads` собирается из `content.json` и ведёт на GitHub Releases:

```text
https://github.com/tritonJS826/noesis/releases/latest/download/<asset>
```

Сейчас это девять файлов:

| Платформа | Архитектура | Файлы |
| --- | --- | --- |
| Linux | x86_64 | `noesis-{cli,tui,gui}-linux-amd64` |
| Windows | x86_64 | `noesis-{cli,tui,gui}-windows-amd64.exe` |
| macOS | arm64 | `noesis-{cli,tui,gui}-macos-arm64` |

Имена должны совпадать с тем, что публикует
`.github/workflows/release.yml` и `CICD/build-release.sh`. Релизные сборки
собираются с локальной моделью `qwen2.5:7b`; это делает бесплатный запуск
модели по умолчанию, без облачных API.

## Локальный просмотр

Из-за `fetch('content.json')` страницы нужно открывать через HTTP, а не через
`file://`:

```sh
python3 -m http.server 8000 -d landings
```

Затем откройте <http://localhost:8000> или
<http://localhost:8000/?lang=en>. Формы на обычном сервере только
отображаются: для реальной отправки нужен Netlify.

## Netlify Forms

На сайте две формы с уникальными именами:

| Имя формы | Где находится | Успешный редирект |
| --- | --- | --- |
| `feedback-footer` | `index.html`, компактная форма в подвале | `/thanks.html` |
| `feedback` | `feedback.html`, полная форма | `/thanks.html` |

Общие поля: `name`, `email`, `message`; у полной формы ещё `topic`. Скрытые
поля: `form-name` (имя формы) и `language` (`ru` / `en`). Для защиты от ботов
используется honeypot-поле `bot-field` и атрибут
`netlify-honeypot="bot-field"`.

Netlify Forms не требуют JavaScript: формы размечены статически и
обнаруживаются при деплое. После первого деплоя проверьте **Forms** в панели
Netlify и настройте уведомления.

## Деплой

- **Publish directory — `landings/`.** В корне репозитория есть
  `netlify.toml` с этим значением. Если публиковать корень репозитория,
  `styles.css` и `/thanks.html` сломаются.
- `app.js` загружает `content.json` относительным путём, поэтому страницы
  должны лежать рядом с этими файлами.
- `action="/thanks.html"` и ссылки в шапке корневые. Если сайт будет жить в
  подпапке, замените их на путь с префиксом.
- В формах есть предупреждение: заявки обрабатываются через Netlify, поэтому
  не стоит отправлять в них личные заметки и другие чувствительные данные.

## CI/CD

Релизный пайплайн описан в `CICD/README.md` и
`.github/workflows/release.yml`. Он собирает девять бинарников на
Ubuntu/Windows/macOS, загружает их в GitHub Releases и создаёт тег при
ручном запуске. После релиза ссылки на лендинге начинают работать без
дополнительных правок.
